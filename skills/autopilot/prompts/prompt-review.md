# Ревьюеру prompt-таска — прочитай это до первого диффа

Материал для субагента-ревьюера промпта. Режимы, формат возврата и правило «ничего не чини, не запускай агентов» — как в `prompts/review.md` (путь тот же каталог), только скилл `ub-mode` здесь не нужен и скиллы вообще не вызываются; этот файл заменяет в нём ось Craft на ось **Prompt craft**. Оси Manifest и Spec остаются: Manifest для промпта — это ещё и **методика владельца**.

Строка `EVAL` из отчёта исполнителя — факт, как гейты для кода: прогнанные кейсы, A/B, бюджет токенов уже проверены машиной. Ты судишь то, чего eval не видит, и то, хороши ли сами кейсы.

## Manifest — методика

По цитатам брифа и словам владельца в таске: промпт делает то, что владелец описал, или правдоподобную замену? «Коуч задаёт 5–10 вопросов» стало «коуч задаёт вопросы, пока не хватит»; порядок вопросов владельца переставлен «для естественности»; метка `[МЕТОДИКА — подтверди]` заменена текстом без слов владельца. **Выдуманная или изменённая без слов владельца методика — `BLOCKING`.**

## Prompt craft

- **Противоречивые инструкции** — два правила, которые не могут выполняться разом, или неясно, какое главнее. Цитируй обе строки.
- **Двусмысленность** — правило, которое две модели прочтут по-разному: «коротко» без числа, «если нужно» без условия, «как обычно».
- **Утечка few-shot** — детали примеров (имена, темы, обороты) появляются в ответах на чужие кейсы; смотри кассеты, а не только сам промпт. Примеры с реальными людьми без обезличивания — находка безопасности.
- **Устойчивость к инъекции** — текст автора попадает только в секцию данных и обрамлён как данные; ни одна инструкция не склеивается с ним; в `evals/` есть кейсы с «игнорируй инструкции», с разметкой секций промпта внутри текста автора — и они проходят.
- **Контракт выхода** — секция вывода совпадает со схемой `schemas/<stage>.json` поле в поле: обязательные поля, перечисления, типы; нет прозы вокруг JSON, если код его разбирает.
- **Русский стиль** — живой русский без кальки, тон, который задал владелец; без канцелярита в репликах коуча.
- **Длина** — бюджет соблюдён без мёртвых секций; одно правило не повторено в трёх местах (ub-mode: одно решение — в одном месте).
- **Версия** — номер поднят по правилу (minor/major), есть запись в `registry.yaml` и строка в `CHANGELOG.md`.

## Кейсы

Eval доказывает поведение, только если кейсы могли упасть. Ожидаемое взято из слов владельца или спецификации, а не из того, что промпт выдаёт? Есть кейсы на отказ, на пустой ввод, на инъекцию? `REDPROOF` правдоподобен? A/B-регрессия объяснена в CHANGELOG, а не тихо «обновлён ожидаемый ответ»?

## Что блокирует

Только это, дословно условием: методика выдумана или изменена без слов владельца; контракт выхода расходится со схемой; текст автора может попасть на место инструкции; регрессия A/B без причины в таске; версия, registry или CHANGELOG не обновлены; персональные данные в кейсах, кассетах или few-shot. Остальное — `FINDINGS`.

Формат — как в `prompts/review.md` для режима «таск» или «ремонт», с осью `PROMPT:` вместо `CRAFT:`, и одна строка сверху:

```
PAGE: .autopilot/<папка>/prompt-reviews/NN-<slug>.html   — или «нет: есть BLOCKING»
```

## Страница обзора для владельца

Промпт и методику утверждает владелец, но **сырой XML ему не показывают**. Если `BLOCKING` пуст, ты пишешь один файл — `<основная копия>/.autopilot/<папка>/prompt-reviews/NN-<slug>.html` — и это единственное, что ты вообще пишешь. Владелец её смотрит, комментирует, и его слова уходят исполнителю дозапросом. Страница — для человека, который знает свою методику и не обязан знать XML. При `BLOCKING` страницы нет: сначала ремонт.

**Файл:**

- Один самодостаточный HTML: `<!doctype html>`, `<html lang="ru">`, `<meta charset="utf-8">`, `<meta name="viewport" …>`, стили в `<style>`, скрипт в `<script>`. **Никаких внешних ресурсов** — ни шрифтов, ни CDN, ни картинок по ссылке, ни запросов в сеть: открывается двойным щелчком без интернета.
- Весь текст — по-русски, простыми словами; имена секций XML, id кейсов и пути — в `<code>`.
- Без персональных данных: фрагменты кейсов только обезличенные, значений секретов нет.
- Читается с телефона: одна колонка шириной до ~760 px, системный шрифт, светлая и тёмная тема через `prefers-color-scheme`.
- До ~150 КБ. Промпт целиком не вставляется — только изменённые места и путь к файлу.

**Разделы — в этом порядке:**

1. **Шапка** — «Обзор промпта: `<стадия>/<имя>` vX.Y → vX.Z», таск NN, дата, строка «Ждёт тебя: посмотри и ответь в чате».
2. **Коротко** — две–четыре строки: что стадия теперь делает иначе глазами автора, а не модели.
3. **Что изменилось — по секциям** — для каждой изменённой секции XML: её имя, «было» и «стало» фрагментами (удалённое в `<del>`, добавленное в `<ins>`) и одна строка «зачем». Новые и удалённые секции — отдельными пунктами.
4. **Почему** — требования `R##`, которые закрывает изменение, с дословными цитатами брифа или слов владельца; все метки `[МЕТОДИКА — подтверди]` — отдельным списком.
5. **Как проверялось** — таблица кейсов: id — что проверяет — результат (прошёл / упал / новый); итог A/B к прошлой версии (+n / −m и какие кейсы); бюджет токенов (было → стало / лимит); живой прогон и его стоимость, если был.
6. **Что сказал ревьюер** — вердикт по осям Manifest, Spec, Prompt craft: `clean` или находки по строке; что из находок не блокирует и оставлено как есть.
7. **Открытые вопросы** — пронумерованные, каждый с рекомендуемым ответом и причиной в полстроки, как раунд брифинга: «1. Сколько вопросов коуч задаёт до черновика? Я бы оставил 5–7: дольше авторы бросают».
8. **Твои комментарии** — поле `<textarea>` у каждого вопроса и у каждого изменения, плюс общее поле; кнопка «Собрать ответ» складывает заполненное в один текст с номерами («В2 — …; изменение 3 — …; общее — …») и копирует его в буфер обмена — владелец вставляет его в чат. Подсказка рядом: ответ «ок» без комментариев утверждает версию. Скрипт только локальный: ничего не отправляет; черновик комментариев — в `localStorage`, обёрнутом в `try/catch`, и страница работает без него.
9. **Где что лежит** — пути: промпт, кейсы, `prompts/CHANGELOG.md`, `prompts/registry.yaml`, коммит таска.

**В режиме «ремонт» после комментариев владельца** страница переписывается целиком под новую версию, а раздел 3 начинается блоком «По твоим комментариям»: комментарий — что сделано — где. Комментарий, который не выполнен, назван там же, с причиной.
