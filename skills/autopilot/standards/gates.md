# `make gates` — контракт детерминированных гейтов

Читается в Фазе 4, когда режется таск, который строит команду проверки (таск 01 или первый `Тип: infra`), и передаётся его исполнителю путём. Больше никому: оркестратор и ревьюеры видят только вывод гейтов.

Гейты — то, что ub-mode требует механически и что ревьюер не должен проверять глазами: сложность, дублирование, сила тестов. Их вывод — факт, а не находка (`prompts/review.md`).

## Что обязано быть в проекте

| Гейт | Инструмент | Порог | Красный, когда |
|---|---|---|---|
| CRAP | `unclebob/crapper` по покрытию `pytest --cov` | `< 10` на функцию | хоть одна изменённая функция ≥ 10 |
| Дубли | `unclebob/dryer` | `< 0.8` сходства | хоть одна пара ≥ 0.8 в изменённых файлах |
| Мутанты | `unclebob/mutator` (ищет `../crapper` рядом) | 0 выживших | хоть один выживший мутант в изменённых строках |

Инструменты ставит тот же таск — в `tools/gates/` проекта или туда, где их README велит; **флаги сверяются с README инструмента при установке**, примеры ниже — по описаниям инструментов, не из запуска. Системные пакеты не ставятся: инструмент, которому нужен системный пакет, — `BLOCKED` с его названием.

## Интерфейс команды

```
make gates                    # все файлы — ночью и в Фазе 8
make gates CHANGED=1          # только изменённые с BASE — в каждом таске
make gates CHANGED=1 BASE=<sha>   # BASE по умолчанию: merge-base с основной веткой
```

- **Выход ≠ 0, если красный хоть один гейт.** Сборка, тайпчек и линтер — в команде проверки (`make check`), не здесь; их красный — красный прогон.
- **Молчание — не зелёный.** Охват непустой, а отчёт инструмента не разобран или пуст (ни одной записи CRAP, нет итоговой строки мутаций) — гейт красный, а не «crap max 0.0» и «0/0 убито». Это проверяется тестом самого сводного скрипта.
- **Клоны инструментов закреплены на коммите** (в `Makefile` или рядом), и существующий клон сверяется с ним перед запуском: другой коммит — перечекаут или отказ, иначе гейты у двух исполнителей считают по-разному.
- **Вывод — сводка, не простыня:** последние строки всегда такие, чтобы `| tail -15` их показал, и одна итоговая строка в формате контракта исполнителя:

```
GATES: crap max 7.4 · dry 0 пар ≥0.8 · mutants 38/41 убито, выжившие: src/core/fsm.py:42 «<» → «<=»
```

- `CHANGED=1` считает изменённым всё, что отличается от `BASE`, включая незакоммиченное: исполнитель гоняет гейты до коммита, оркестратор — после коммита в worktree, и оба видят одно.
- Ложные дубли в фикстурах, схемах и eval-кейсах — в белый список (`.dryer-ignore` или флаг исключения), с комментарием «почему»; код продукта в белый список не попадает.

## Пример для Python-проекта (сверить флаги с README инструментов)

```make
MAIN   ?= main
BASE   ?= $(shell git merge-base HEAD $(MAIN) 2>/dev/null || git rev-list --max-parents=0 HEAD)
PY_CHANGED = $(shell git diff --name-only --diff-filter=AMR $(BASE) -- 'src/*.py' 'src/**/*.py')
SCOPE  = $(if $(CHANGED),$(PY_CHANGED),src)

check:
	uv run ruff check . && uv run mypy src && uv run pytest -q

gates: gates-wait
	@uv run pytest -q --cov=src --cov-report=xml >/dev/null
	@./tools/gates/crapper --use-existing-coverage --threshold 10 $(SCOPE)
	@./tools/gates/dryer --threshold 0.8 $(SCOPE)
	@./tools/gates/mutator --use-existing-coverage --max-workers $(LS_GATES_JOBS) --test-command "uv run pytest -q -x" $(SCOPE)
	@uv run python tools/gates/summary.py     # одна строка GATES: … для контракта
```

Пустой `SCOPE` при `CHANGED=1` (таск не тронул Python) — гейты зелёные, строка `GATES: нет изменённого кода`.

## Нагрузка на машину — `LS_GATES_JOBS`

Мутатор запускает тесты на каждый мутант, и несколько исполнителей с гейтами одновременно кладут машину (на ноутбуке без вентилятора средняя нагрузка доходила до ~100 при двух десятках процессов pytest). Поэтому:

- **Мутатор — только по изменённым файлам** (`CHANGED=1`, охват — `SCOPE`); полный прогон — только ночью и в одиночку (ниже).
- **Число воркеров мутатора — `LS_GATES_JOBS`** (по умолчанию 2): `--max-workers $(LS_GATES_JOBS)`.
- **Перед гейтами — ожидание**: пока на машине больше 8 процессов pytest или идёт чужой мутатор, гейты не стартуют. Отдельными строками рецепта, чтобы шаблон не находил собственную оболочку:

```make
LS_GATES_JOBS ?= 2

gates-wait:
	@while [ "$$(pgrep -f pytest | wc -l)" -gt 8 ]; do sleep 20; done
	@while pgrep -f '[t]ools/gates/mutator' >/dev/null; do sleep 20; done
```

На macOS у `pgrep` нет флага `-c` — счёт только через `| wc -l`; с `pgrep -fc …` там получается пустая строка, и цикл выходит сразу, ничего не дождавшись.

## Ночью

Полный прогон мутаций (`make gates` без `CHANGED`) медленный — он идёт ночной задачей (`phases/5-night.md`), когда очередь пуста и никто больше не гоняет гейты, с тем же `LS_GATES_JOBS` и ожиданием; выжившие уходят в `concerns`, не в ремонт.
